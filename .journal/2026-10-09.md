# jour — Dev Journal

---

## 2026-10-09 — Initial build session

### What we built

A minimal CLI journal tool written in Python, installable as the `jour` command.

---

### Architecture

```
jour_cli/
├── __init__.py
├── config.py     — defaults, deep-merge, load_config(), editor detection
├── db.py         — SQLite schema, init, index_note(), tag queries
├── notes.py      — notes make, notes list
├── tags.py       — tags list, tags show (SQLite-backed)
├── search.py     — grep-based full-text search
└── main.py       — argparse entrypoint, command routing
```

Data lives in `~/.jour/`:
- `*.jmd` — note files with YAML front matter
- `.jourconfig` — optional YAML user config (deep-merged over defaults)
- `jour.db` — SQLite tag index

---

### Notes storage

Notes are stored as flat files:

```
~/.jour/20261009203000_a3f2b1c8.jmd
```

**Filename format:** `{YYYYmmddHHMMSS}_{8-char uuid hex}.jmd`

The timestamp prefix keeps files chronologically sortable. The UUID hex suffix makes collisions impossible even under tight automation loops — an earlier pure-timestamp design (`%Y%m%d%H%M`) caused files created in the same minute to overwrite each other, which was caught by the smoke tests.

Each file has YAML front matter:

```yaml
---
layout: default
title: "2026-10-09 20:30"
date: 2026-10-09 20:30
tags: ['work', 'daily']
---

Note body here.
```

---

### Note creation — input priority

`jour notes make` resolves the note body in this order:

1. `--note` / `-n` flag
2. Piped stdin (`cat file.txt | jour notes make`)
3. Opens editor (falls through if no body provided)

If a body is provided via flag or pipe, the editor is skipped entirely — mirrors `git commit -m`.

Tags are set via `--tag` / `-t` as a comma-delimited string: `-t "work,daily,ideas"`.

### Tag indexing — SQLite

Tags were initially scanned on every command (O(n) file reads + YAML parse). Replaced with a SQLite index in `~/.jour/jour.db`.

**Schema:**

```sql
CREATE TABLE notes (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    filename   TEXT    NOT NULL UNIQUE,
    filepath   TEXT    NOT NULL,
    created_at TEXT    NOT NULL
);

CREATE TABLE tags (
    id      INTEGER PRIMARY KEY AUTOINCREMENT,
    note_id INTEGER NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
    tag     TEXT    NOT NULL
);

CREATE INDEX idx_tags_tag     ON tags(tag);
CREATE INDEX idx_tags_note_id ON tags(note_id);
```

Schema is created via `init_db()` which is called inside `load_config()` on every startup — idempotent via `CREATE TABLE IF NOT EXISTS`. `index_note()` upserts the note row and replaces its tag rows atomically. `tags list` and `tags show` are now O(1) index lookups.

### Cross-platform editor

Default editor is resolved at runtime in `_default_editor()`:

```
$VISUAL → $EDITOR → "open -t" (macOS) / "xdg-open" (Linux)
```

Editor is invoked via `shlex.split(cmd) + [filepath]` — no `shell=True`, path is a safe separate argument.

### Install

```sh
chmod +x install.sh
./install.sh
```

Installs via `pip3 install --user -e .` into `~/.local/bin`. Script is POSIX sh compatible.

---

### Testing — Podman container

Tests run inside a fresh Ubuntu 24.04 container via Podman. No test deps installed on the host.

```sh
./podman-test.sh
```

Runs two suites sequentially, each in its own container (clean state):

| Suite | File | Tests |
|---|---|---|
| Smoke | `tests/smoke.sh` | Binary presence, note creation (pipe/flag/editor), tags, search |
| Tags | `tests/test_tags.sh` | Count accuracy, increment, show, multi-note, empty query, ordering, whitespace normalisation, idempotency |

**Containerfile** — Ubuntu 24.04, Python 3 via apt, venv at `/opt/jour-venv`, `pip install -e .`.

### Decisions log

| Decision | Rationale |
|---|---|
| Flat `.jmd` files | Human-readable, portable, no lock-in |
| UUID suffix on filenames | Pure timestamp (minute precision) caused overwrites under automation |
| SQLite for tag index | O(n) file scan was fine for small sets but doesn't scale; sqlite3 is stdlib |
| `CREATE TABLE IF NOT EXISTS` on every boot | Idempotent bootstrap — no migration tooling needed at this scale |
| POSIX sh for scripts | zsh-specific `[[` syntax excluded Linux; case statement + sh shebang covers both |
| No `shell=True` for editor | Unquoted path interpolation into shell string is a security/correctness hazard |
